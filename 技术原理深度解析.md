## 1. JWT 认证与线程安全机制

### 1.1 JWT 结构解析

JWT（JSON Web Token）由三部分组成，用点号分隔：
```
Header.Payload.Signature
```

**Header（头部）**：
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

**Payload（载荷）**：
```json
{
  "userId": "123456",
  "username": "admin",
  "iat": 1704067200,
  "exp": 1704153600
}
```

**Signature（签名）**：
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

### 1.2 线程安全问题分析

** Hutool JWT 的问题：**

```java
// Hutool 的非线程安全实现
public Map<String, Object> parsePayload(String token) {
    JWTSigner signer = createSigner();
    return JWTUtil.parseToken(token)  // 返回共享的 JWT 对象
            .setSigner(signer)        // 多线程下状态被覆盖
            .getPayloads();           // 可能返回错误的 payload
}
```

**问题根源：**
- `JWTUtil.parseToken()` 返回的 `JWT` 对象内部维护着解析状态
- `setSigner()` 修改了对象的内部状态
- 高并发时，线程 A 设置的 signer 可能被线程 B 覆盖
- 导致解析出的 `userId` 为 null 或错误

**JJWT 的线程安全实现：**

```java
@Component
public final class JwtUtil {
    
    public String getUserId(String token) {
        // 每次调用都创建新的解析器实例，无共享状态
        Claims claims = Jwts.parser()
                .verifyWith(getSigningKey())  // 设置验证密钥
                .build()                       // 构建独立的解析器
                .parseSignedClaims(token)      // 解析 token
                .getPayload();
        
        Object userId = claims.get("userId");
        return userId != null ? userId.toString() : null;
    }
}
```

**JJWT 线程安全的关键设计：**

1. **不可变对象模式**：`Jwts.parser()` 返回的 `JwtParserBuilder` 是独立的构建器
2. **无共享状态**：每个请求创建新的解析器，不存在并发修改
3. **函数式 API**：链式调用返回新对象，不修改原对象

### 1.3 密钥生成原理

```java
private SecretKey getSigningKey() {
    String secret = tokenProperties.getSecret();
    // HS256 要求密钥至少 256 位（32 字节）
    if (secret.length() < 32) {
        secret = String.format("%-32s", secret).replace(' ', '0');
    }
    return Keys.hmacShaKeyFor(secret.getBytes());
}
```

**HMAC-SHA256 算法原理：**
- 密钥长度必须 ≥ 256 位（32 字节）
- 使用 `Keys.hmacShaKeyFor()` 确保密钥符合规范
- 密钥过短会自动填充，保证安全性

## 2. Spring Security 过滤器链与权限控制

### 2.1 过滤器链架构

```
请求 → JwtAuthenticationFilter → UsernamePasswordAuthenticationFilter 
     → AuthorizationFilter → 业务代码
```

**核心过滤器实现：**

```java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    
    private final JwtUtil jwtUtil;
    private final ISysUserService userService;
    private final TokenProperties tokenProperties;
    private final RedisUtil redisUtil;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) 
                                    throws ServletException, IOException {
        // 1. 提取 Token
        String token = extractTokenFromRequest(request);
        
        if (token != null && jwtUtil.verifyToken(token)) {
            try {
                // 2. 解析用户ID
                String userIdStr = jwtUtil.getUserId(token);
                Long userId = Long.valueOf(userIdStr);
                
                // 3. 单点登录验证 - 检查 Redis 中的 token
                String redisKey = tokenProperties.getRedisTokenPrefix() + userId;
                Object cachedToken = redisUtil.get(redisKey);
                
                if (cachedToken == null || !cachedToken.toString().equals(token)) {
                    log.warn("Token已失效或已被新登录替换");
                    filterChain.doFilter(request, response);
                    return;
                }
                
                // 4. 加载用户权限
                List<String> permissions = userService.getPermissions(userId);
                List<SimpleGrantedAuthority> authorities = permissions.stream()
                        .map(SimpleGrantedAuthority::new)
                        .collect(Collectors.toList());
                
                // 5. 构建认证对象
                UsernamePasswordAuthenticationToken authToken = 
                    new UsernamePasswordAuthenticationToken(
                        userId.toString(), null, authorities);
                
                // 6. 设置 Security 上下文
                SecurityContextHolder.getContext().setAuthentication(authToken);
                
            } catch (Exception e) {
                log.error("Cannot set user authentication: {}", e.getMessage());
            }
        }
        
        // 继续过滤器链
        filterChain.doFilter(request, response);
    }
}
```

### 2.2 单点登录（SSO）实现原理

**Redis Token 存储结构：**
```
Key: auth:token:{userId}
Value: {jwt_token}
TTL: 24小时
```

**登录流程：**
1. 用户登录成功 → 生成 JWT
2. 将 `auth:token:123` = `jwt_token` 存入 Redis
3. 后续请求携带 JWT
4. 过滤器验证 JWT 与 Redis 中的是否匹配

**踢下线机制：**
- 新登录会覆盖 Redis 中的旧 token
- 旧 token 在过滤器中被判定为无效
- 实现单点登录：同一账号只能在一个地方登录

## 3. ThreadLocal 用户上下文传递

### 3.1 ThreadLocal 原理

```java
public class UserContextHolder {
    // ThreadLocal 为每个线程维护独立的变量副本
    private static final ThreadLocal<UserInfo> USER_CONTEXT = new ThreadLocal<>();
    
    public static void setCurrentUser(UserInfo userInfo) {
        USER_CONTEXT.set(userInfo);  // 绑定到当前线程
    }
    
    public static UserInfo getCurrentUser() {
        return USER_CONTEXT.get();   // 获取当前线程绑定的值
    }
    
    public static void clear() {
        USER_CONTEXT.remove();       // 清理，防止内存泄漏
    }
}
```

**ThreadLocal 内存模型：**
```
Thread-1 → ThreadLocalMap → UserInfo(userId=1)
Thread-2 → ThreadLocalMap → UserInfo(userId=2)
Thread-3 → ThreadLocalMap → UserInfo(userId=3)
```

每个线程有独立的 `ThreadLocalMap`，互不影响。

### 3.2 在过滤器中设置上下文

```java
@Override
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain) {
    try {
        // 验证通过后设置上下文
        UserInfo userInfo = UserInfo.builder()
                .userId(userId)
                .roles(new HashSet<>(roles))
                .permissions(new HashSet<>(permissions))
                .build();
        
        UserContextHolder.setCurrentUser(userInfo);
        
        // 继续处理请求
        filterChain.doFilter(request, response);
    } finally {
        // 请求完成后必须清理，避免内存泄漏
        UserContextHolder.clear();
    }
}
```

**为什么要在 finally 中清理？**
- Tomcat 使用线程池复用线程
- 如果不清理，下次请求可能获取到旧的用户信息
- 导致严重的安全问题（A 用户看到 B 用户的数据）

### 3.3 在业务代码中使用


### 5.3 分页查询实现

```java
@Service
public class SealApplyServiceImpl extends ServiceImpl<SealApplyMapper, SealApply> 
        implements ISealApplyService {
    
    @Override
    public PageResult<SealApplyVO> pageSealApply(SealApplyPageQuery queryParams) {
        // 1. 创建分页对象
        Page<SealApply> page = new Page<>(queryParams.getPageNum(), 
                                          queryParams.getPageSize());
        
        // 2. 构建查询条件
        LambdaQueryWrapper<SealApply> wrapper = new LambdaQueryWrapper<>();
        if (StrUtil.isNotBlank(queryParams.getKeyword())) {
            wrapper.like(SealApply::getApplyReason, queryParams.getKeyword());
        }
        
        // 3. 执行分页查询
        IPage<SealApply> result = baseMapper.selectPage(page, wrapper);
        
        // 4. 转换 VO
        List<SealApplyVO> voList = result.getRecords().stream()
                .map(this::convertToVO)
                .collect(Collectors.toList());
        
        return PageResult.success(voList, result.getTotal());
    }
}
```

**分页原理：**
- MyBatis-Plus 自动拦截 SQL
- 先执行 `SELECT COUNT(*)` 获取总数
- 再执行带 `LIMIT` 的分页查询

## 6. 区块链存证技术

### 6.1 存证数据结构设计

```java
@Data
@TableName("blockchain_evidence")
public class BlockchainEvidence {
    
    private Long id;
    
    // 业务关联
    private String businessType;  // 业务类型：SEAL_APPLY、SEAL_APPROVAL
    private Long businessId;      // 业务ID
    
    // 存证内容
    private String dataHash;      // 数据哈希（SHA-256）
    private String txHash;        // 区块链交易哈希
    private String blockNumber;   // 区块号
    
    // 时间戳
    private LocalDateTime evidenceTime;
}
```

### 6.2 哈希计算原理

```java
@Component
public class BlockchainEvidenceServiceImpl implements IBlockchainEvidenceService {
    
    private String calculateDataHash(Object data) {
        String jsonStr = JSONUtil.toJsonStr(data);
        return SecureUtil.sha256(jsonStr);  // SHA-256 哈希
    }
}
```

**SHA-256 特性：**
- 单向性：无法从哈希反推原文
- 抗碰撞：不同数据几乎不可能产生相同哈希
- 雪崩效应：微小改动导致哈希完全不同

### 6.3 存证验证流程

```java
public BlockchainVerifyResultVO verifyEvidenceWithDataConsistency(Long evidenceId) {
    // 1. 查询存证记录
    BlockchainEvidence evidence = getById(evidenceId);
    
    // 2. 查询当前业务数据
    Object currentData = getBusinessData(evidence.getBusinessType(), 
                                         evidence.getBusinessId());
    
    // 3. 计算当前数据哈希
    String currentHash = calculateDataHash(currentData);
    
    // 4. 比对哈希
    boolean dataConsistent = currentHash.equals(evidence.getDataHash());
    
    // 5. 查询区块链验证交易
    boolean blockchainValid = verifyOnBlockchain(evidence.getTxHash());
    
    return BlockchainVerifyResultVO.builder()
            .dataConsistent(dataConsistent)
            .blockchainValid(blockchainValid)
            .build();
}
```

## 7. PDF 盖章与数字签名

### 7.1 PDF 文档结构

```
PDF 文档结构：
├── Header (%PDF-1.4)
├── Body（对象集合）
│   ├── Catalog（文档根）
│   ├── Pages（页面树）
│   └── Page（具体页面）
│       ├── Content Stream（内容流）
│       └── Resources（资源：字体、图片等）
├── Cross-Reference Table（交叉引用表）
└── Trailer（尾部，指向根对象）
```

### 7.2 盖章实现原理

```java
@Service
@RequiredArgsConstructor
public class PdfStampServiceImpl implements IPdfStampService {
    
    public byte[] stampPdfWithEvidence(SealStampForm formData) throws IOException {
        // 1. 加载 PDF 文档
        PDDocument document = PDDocument.load(new File(formData.getFilePath()));
        
        // 2. 获取印章图片
        PDImageXObject sealImage = PDImageXObject.createFromFile(
                sealInfo.getImageUrl(), document);
        
        // 3. 遍历所有页面盖章
        for (PDPage page : document.getPages()) {
            PDPageContentStream contentStream = new PDPageContentStream(
                    document, page, PDPageContentStream.AppendMode.APPEND, true);
            
            // 在指定位置绘制印章
            contentStream.drawImage(sealImage, 
                    formData.getX(), 
                    formData.getY(), 
                    formData.getWidth(), 
                    formData.getHeight());
            
            contentStream.close();
        }
        
        // 4. 保存并返回字节数组
        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        document.save(baos);
        document.close();
        
        return baos.toByteArray();
    }
}
```

```java
private void drawRidingSeal(PDDocument document, PDImageXObject sealImage,

    float sealHeight = 100;
    
    for (int i = 0; i < pageCount; i++) {
```

## 总结

SealFlow 系统融合了多种企业级技术：

1. **安全认证**：JWT + Spring Security + Redis SSO
2. **并发处理**：ThreadLocal 线程隔离 + JJWT 线程安全
3. **流程引擎**：Flowable BPMN 工作流
4. **数据访问**：MyBatis-Plus 简化 CRUD
5. **可信存证**：区块链 + SHA-256 哈希
6. **文档处理**：PDFBox 电子签章

这些技术共同构建了一个安全、可靠、可扩展的印章管理系统。
